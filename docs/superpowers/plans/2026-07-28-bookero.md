# Bookero Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Bookero end-to-end — Spring API, Python analytics, Next.js web, algorithm pack, and Phase 1–6 docs — so an evaluator can run a full-loop dynamic-pricing demo from Docker Compose.

**Architecture:** Simulation-first monorepo. Postgres is system of record; Spring owns domain + algorithms; Python owns ETL/ML/metrics; Next.js is role-based traveler/ops/Algorithm Lab. Lab and live reprice share the same algorithm implementations.

**Tech Stack:** Java 21, Spring Boot 3.3+, Flyway, PostgreSQL 16, Python 3.12, FastAPI, Pandas/NumPy/scikit-learn, Next.js 15 (TypeScript), Docker Compose.

**Standards:** Senior-optimized code; sparse comments; conventional commits with **exactly one file per commit**. Follow `BUILD.md` + `docs/superpowers/specs/2026-07-28-bookero-design.md`.

**Heuristic (`time_pressure_heuristic`) must:** adjust price by days-to-departure and load factor with clear formula in the doc.

**ML (`demand_ml`):** Python train/forecast; Spring `revenue_optimize` reads forecast HTTP.
